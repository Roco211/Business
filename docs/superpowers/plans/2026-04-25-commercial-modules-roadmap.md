# Business 商业模块路线图（E4）

生成时间：2026-04-25
目标：在不制造假数据的前提下，把当前商品/库存/AI经营助手核心闭环扩展为可商用的门店经营系统。

## 当前已开放模块

1. 商品管理
   - 商品新增、列表、详情、软删除；
   - 多租户/门店隔离；
   - 删除后保留历史审计。

2. 库存管理
   - 正式入库/出库 API；
   - 库存流水 ledger 作为事实源；
   - 快照 projection；
   - 单商品审计 API。

3. AI经营助手
   - 自然语言查询；
   - Chat/Voice/Photo 库存写操作 confirmation-first；
   - 待确认任务审批后才落账；
   - 官方职责名称：AI运营协调官、经营数据分析员、库存风控专员、商品档案管理员、经营策略顾问。

4. PC/H5 工作台
   - 登录；
   - 租户/门店上下文；
   - 真数据 KPI；
   - 商品/库存/流水/待确认任务入口；
   - 未实现模块仅显示“即将上线”，不展示假数据。

## 下一批商业模块优先级

### F1 订单/销售单

目标：把当前库存出库与销售流水从“库存操作”升级为“销售单”。

核心对象：
- SalesOrder
- SalesOrderLine
- PaymentRecord
- RefundRecord（后续）

必备能力：
- 新建销售单；
- 销售单确认后生成库存出库 ledger；
- 支持现金/微信/支付宝/银行卡等支付方式字段；
- 销售单撤销需要生成反向库存事件，不能硬删事实；
- Dashboard 今日销售额/销售笔数从销售单聚合。

### F2 客户档案

目标：为个体户提供轻量客户记账和复购分析。

核心对象：
- Customer
- CustomerContact
- CustomerTag

必备能力：
- 客户新增/搜索；
- 与销售单关联；
- 欠款/赊账字段后续接入财务模块；
- 客户跨租户严格隔离。

### F3 供应商/采购

目标：完善进货闭环。

核心对象：
- Supplier
- PurchaseOrder
- PurchaseOrderLine
- PurchaseReceipt

必备能力：
- 采购建议生成采购草稿；
- 采购收货后生成入库 ledger；
- 供应商历史价格用于进货建议。

### F4 财务流水

目标：从经营数据升级为可对账的现金流。

核心对象：
- CashLedger
- Account
- Settlement

必备能力：
- 销售收款、采购付款、退款、调整；
- 与销售单/采购单/库存事件关联；
- Dashboard 增加利润、应收、应付。

### F5 营销/会员/售后

目标：在核心交易稳定后增强增长和服务能力。

核心对象：
- Campaign
- Coupon
- MemberProfile
- AfterSalesTicket

必备能力：
- 基于真实销售和客户数据生成营销建议；
- 售后不直接改库存，必须走 confirmation 或正式反向单据。

## 前端承接规则

- 后端领域模型未完成前，前端只展示“即将上线/能力边界”。
- 不写静态假订单、假客户、假财务数字。
- 新模块上线必须先有 HTTP 回归测试，再开放 PC/H5 页面。
- AI 建议涉及业务写入时必须生成 confirmation，不允许前端直接落账。

## 建议推进顺序

1. F1 销售单：商业价值最高，能让 Dashboard KPI 更真实；
2. F3 采购/供应商：与库存补货建议联动；
3. F2 客户：支撑复购和赊账；
4. F4 财务流水：支撑商业化报表；
5. F5 营销/售后：依赖前面真实数据沉淀。
